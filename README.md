## 0.2.1 连接状态修正

修复断开车机 Wi-Fi 或退出后返回应用仍显示“已连接”的问题：

## 0.1.2 连接修正

针对“原版可连、复刻版无法连接”的反馈，逐条核对原 APK 的实际方法后，修复以下兼容缺口：

- Android 原生读取 Wi-Fi 的 IPv4、网关和掩码，将本应用的连接与下载绑定到 Wi-Fi，避免无互联网的车机热点被移动数据分流。

- A7 识别接受 HTTP 200 的简短 `OK` 响应，不再额外要求包含 `DVR` 或属性名；继续拒绝 HTML。
- 星越 L 的 A7 普通/紧急录像目录改为 `DCIM / EVENT`。
- 新增查找进度、停止查找、网络自检、可复制的连接诊断。自检只检查本应用使用 Wi-Fi 的能力，不扫描网络。

## 手机测试

1. 开启车机热点，在车机上打开一次原厂记录仪应用。
2. 手机连接车机热点，即使系统显示“无互联网”也保留连接。
3. 打开本应用，会自动尝试连接；也可点击「连接记录仪」，或扫码连接车机热点。
4. 网络重连后，可在设备首页下拉重新连接。若仍失败，在设置中导出运行日志供排查。

连接后先核对时长与封面并播放一段原片，再到「设置与帮助 → 下载与保存 → 选择目录」验证自定义位置。详细验收步骤见 [0.2.0 功能清单](analysis/FEATURES-A7-0.2.0.md)。

## 开发与验证

```text
npm install
npm run dev
npm run desktop:dev
npm run build
npm test
cargo test --manifest-path src-tauri/Cargo.toml --target-dir src-tauri/target
node tools/check_vehicle_ui.cjs
node tools/check_connection_state_ui.cjs
node tools/check_media_ui.cjs
node tools/check_native_player_ui.cjs
node tools/check_workflows_ui.cjs
```

界面检查要求本地开发页面运行于 1420 端口。媒体检查可通过 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 指定本机 Playwright 模块与 Chrome。连接和媒体检查使用模拟 Tauri 桥接，不会查找或控制真实设备。桌面实时预览、抽帧回退和片段导出需要系统 FFmpeg/FFprobe；Android 不需要另装。

Android 环境需要 Android SDK/NDK、JDK 和 Rust Android target。Windows PowerShell 测试构建：

```powershell
$env:GALAXY_TEST_SIGNING = '1'
npm run tauri -- android build --target aarch64 --apk --ci
```

在无法访问 Google Maven 的网络中，可在构建时设置 `GALAXY_MAVEN_MIRROR=1`，仅对 AndroidX 依赖启用可选镜像；默认仍使用官方源。macOS 本机配置还需设置 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME` 与 `CARGO_TARGET_DIR`。

原 APK 静态报告位于 `analysis/APK-analysis.md`；设计位于 `design/glacier-a/`，0.2.0 播放器和设置截图位于 `analysis/`。演示模式已从当前源码移除，媒体测试文件放在 tools/fixtures/，不随产品前端发布。本轮范围是星越 L 的本地功能，其他车型、iOS 及原作者云端服务尚未移植。
