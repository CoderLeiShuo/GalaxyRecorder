# 0.4.0：播放器、续传、旧录像与连接

目标：2026 款星越 L（A7）。技术栈继续使用 Tauri 2 + React + TypeScript + Rust；Android 的视频解码与系统能力由 Kotlin 插件实现。

## 本次 7 项反馈

| 反馈 | 修改 |
| --- | --- |
| 全屏把整块播放器放大 | 全屏只保留视频表面。电脑使用视频容器的 Fullscreen API，未提供 API 时使用全视口回退；Android 独立视频层铺满屏幕并横屏，隐藏系统栏。自绘播放、进度和退出按钮悬浮，3 秒后自动隐藏；Android 返回键退出全屏。 |
| 大小待确认 | 在线录像通过 Range 响应的 Content-Range 或完整响应的 Content-Length 补读总大小；已保存录像读取文件实际字节数。播放器和列表使用补读值，元数据缓存更新。设备未返回任何长度时不能提供准确大小。 |
| 下载缺少 toast | 成功入队后在播放器弹窗内部显示「已开始下载，可在传输任务中查看」，避免提示被模态弹窗挡住；失败与已在队列中的情况也给出反馈。 |
| 任务续传与删除 | 下载保留 `.part` 与 `.resume` 检查点，使用文件实际长度恢复进度。任务可暂停、继续、逐项删除；再次下载同一段已暂停录像会复用该任务。启动后把中断任务恢复为可继续状态。删除任务/清理历史会清理临时数据并保留已保存录像。 |
| 旧录像被误拦截 | Tauri Android 的 appDataDir 实际为 dataDir，之前 Kotlin 却只允许 filesDir。现在兼容 dataDir/media 与 filesDir/media，并为 FileProvider 增加对应的窄目录。读取、导出、打码和分享共用目录校验。 |
| 重新连 Wi-Fi 后偶发找不到 | 优先当前实际 Wi-Fi 或二维码指定的网络，避免旧绑定优先；扫码等待 IPv4 就绪再请求设备，网络准备和设备发现有短暂重试。首页支持下拉重连，也提供点击重连入口。断网会使进行中的发现结果失效。 |
| 简化连接与打开行为 | 连接页保留连接、扫码及相册识码，不展示地址扫描、手填 IP、自检等操作。打开时自动尝试；已有连接在前台恢复时静默验证，可用就继续使用。进程重启先检查持久会话，再尝试上次设备，失败才发现设备。不会直接把历史地址当作已连接。 |

## 续传一致性

- 保留已收到的字节，网络断开、暂停和进程重启都可继续。已完整接收但本地处理被中断的原片也会保留。
- 继续前核对前 64 KiB 与总长度；有强 ETag 或 Last-Modified 时发送 If-Range。
- 接受 206 时校验起始偏移、结束位置、总长度、响应长度与已知校验标识；错误范围不追加，避免损坏已下载内容。
- 设备返回 200（忽略 Range，或 If-Range 不匹配）时安全重下；416 仅在已收到完整长度且文件核对通过时完成。
- 只在完整下载后发布到媒体库；错误页不会作为录像发布。
- 删除正在执行的任务时先请求停止并等待工作线程退出。若仍在完成系统文件复制，会提示稍后删除；已保存的录像不会被任务删除操作移除。

## 安装后验收

1. 直接覆盖安装 0.4.0，保留原有应用数据。在断网状态先打开一段以前保存的录像，核对播放、大小、分享和导出。
2. 打开车机热点和记录仪；软件首次启动会尝试连接。连接成功后切到后台再返回，应保持连接；彻底重启进程后会先验证之前的设备。
3. 在线播放，进入全屏，等待按钮自动隐藏，再轻触画面、拖动进度或返回；退出应恢复普通播放器。
4. 下载一段较大的录像，看到 toast 后在传输页暂停并继续；再断开热点、重新连接并继续；最后强制关闭应用重新打开，继续该任务。
5. 删除一条暂停任务和一条已完成任务；前者清理临时进度，后者保留已保存录像。
6. 断开并重连车机 Wi-Fi，在首页下拉重连；另验证二维码连热点后自动连接设备。

安装包：`output/galaxy-recorder-0.4.0-playback-resume-arm64-test.apk`。哈希、签名和实际验收状态见 `output/build-info-0.4.0.json`。
