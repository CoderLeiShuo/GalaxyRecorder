# 0.7.0：原版连接方案与本机车型记忆

## 原包依据

输入为用户提供的 `base.apk`（原 APP 0.8.6，包名 com.galaxy.dvrtransfer）。将安装包内容视作协议证据，不执行其中的代码，也不将其文案作为任务指令。SHA-256：`0e737970e57c16dce6a70eac673d089d99609aebc98bdd8846175bd16c4e4371`。

| 方案或能力 | 原版证据 | 新实现 |
| --- | --- | --- |
| A7 | DvrClient.probe，DvrProtocol.Profile | DVR/固件探测，现有 DCIM/EVENT 列表，UDP 49142/53296 与 HTTP 搜索 |
| E5 | RecorderApi.detect/list，E5Discovery | 固件字段识别，MOVIE/SOS/LOCK 目录，HTTP /SD/ 文件访问 |
| L6/L7 | L6Discovery，L6Protocol，L6Api | Vyou GetBaseInfo GET/POST 回退；主动 hello\|vyou、238.238.238.238 的 3702/3703 组播；原厂候选地址；本地 SessionID 与 Certificate 认证 |
| 通用一/二/三 | DvrProtocol.Profile.protocolProfile | 分别映射 E5/A7/L6；X7 旧别名按 E5 处理，原版可见六方案全部提供 |
| 原厂 Wi-Fi 搜索 | NetworkSession.searchE5、E5WifiRules | 使用同一 `[Gg][Ee][Ee][Ll][Yy]_.*` 规则；新 Android 系统选择器确认，旧 Android 扫描并选择候选；密码仅用于本次连接 |
| 扫码、相册识码、系统 Wi-Fi、手动地址 | 原有连接入口 | 保留已有路径，手动地址折叠在次级入口，首页不显示扫描 IP 信息 |
| 记住车型 | VehicleModelStore 与 assets/vehicle_names.json | 原版实际保存用户选择的车型组；新版将设备提供的具体车型与用户确认的信息单独持久保存 |

完整反汇编与方法索引位于既有 `app-disassembly.txt`、`verified-methods.json`。上述流程是独立 Rust/Kotlin 实现，不依赖原作者的云端服务。

## 自动识别与持久化

- 默认自动方案，可在连接页切换；选择保存在应用 settings.json。A7 和 E5 都可能返回 OK，自动模式会进一步使用只读目录响应判断；空目录或不完整信息无法绝对区分时，可明确选择对应方案。
- 首次成功识别设备后补读车型、年款、配置字段。车型与协议严格分离，不再将所有设备固定标成 2026 星越 L，也不从固件日期推断车辆年款。
- 明确提供 VehicleModel/CarModel 等字段与 ModelYear 等字段时，例如星越 L + 2026，显示“星越L2026款”。Vyou 的普通 model 通常是硬件型号，未包含可识别车型时不当成车辆名称。
- 设备未提供完整信息时展示一次确认入口，可填写型号、年款、配置。支持稍后填写，点击首页车型可再次打开。用户确认的数据不会被同设备的缺省字段清掉。
- 最近车辆与最多 12 个设备档案存于本机，沿用设置写锁和临时文件重命名机制。普通保存位置设置不能覆盖车型与连接方案。前端保存显示缓存，重开时优先显示已保存车型，随后读取原生存储。
- 断开连接只清除在线状态；不删除车型档案。演示数据与真实档案分离。
- 优先使用设备 UUID/序列号等标识的摘要区分设备；可用时结合 Wi-Fi 的 BSSID 摘要。没有稳定标识时只能按方案与地址等已知信息记忆，换到相同地址且不提供身份的设备时需手动核对车型，不能声称可以无条件识别每一辆车。
- 车型档案不保存或上传 VIN，不记录 Wi-Fi 密码或原始设备身份字段，不请求原作者更新、配置或统计服务器。

## 连接后的适配与边界

- E5 和 L6 的录像条目携带适配方案，播放、大小读取、下载、续传和缩略图按对应路径校验，不再一律转成 /mnt/mmc/Normal。
- E5 兼容 32 条分页、MOVIE/SOS/LOCK 与 /SD/ 路径；L6 支持普通及紧急 JSON 列表、会话认证、状态读取和基本控制的协议路由。原版 L6 列表的 size 不当作准确字节数，仍由实际媒体请求补读大小。
- L6 的 TCP 私有实时视频通道尚未实现；首页与设置中禁用该方案的实时预览，避免错误使用 A7 的 RTSP 路径。
- 新协议、广播、手机热点搜索和设备控制仍需相应车辆实测。原版车型组清单只代表其配置意图，不能等同于每款车都经过本轮验证。

## 验证记录

- Rust：64 项；包括三类真实本机 HTTP 模拟服务、E5 兼容 OK 响应、L6 GET/POST 识别回退与会话头认证、路径和列表边界、车型字段与年款解析等。
- 前端：32 项，包括已保存车型、演示隔离、全部连接方案和特殊出厂地址边界。
- Android JVM：15 项，新增出厂 Wi-Fi 地址范围验证，保留播放器与文件路径回归；原生搜索代码编译通过。
- 新连接与车型界面：10 项；既有连接状态：11 项；播放器：33 项；原生播放器桥接：9 项；工作流：13 项。合计 187 项。
- 协议服务运行于本机测试监听端口，测试构建按注册的回环地址访问；该测试设施不进入正式安装包，生产地址校验仍只允许局域网与两个明确的出厂地址。
- 浏览器中的车机、Android 系统选择器和文件系统调用使用模拟桥接。界面示例与截图不是实车识别结果。

安装包和签名验证结果见 `output/build-info-0.7.0.json`。本轮不卸载旧应用、不删除录像，也不更换 Tauri + React 技术栈。
