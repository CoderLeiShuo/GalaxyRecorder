# 0.3.0 星越 L 功能补齐记录

日期：2026-10-28。对照原 APK 0.8.6 和本项目 0.2.1，继续以 **2026 款星越 L / A7** 为范围。技术栈保持 Tauri 2 + React + TypeScript + Rust，Android 系统能力通过 Kotlin 插件扩展。

## 本轮确认的缺口与实现

| 原版依据 | 0.2.1 的缺口 | 0.3.0 的实现 |
| --- | --- | --- |
| `AppLog`、`LogsActivity` | 只有本次连接的内存诊断，缺少持久运行日志和文件分享 | 连接、下载、播放、导出日志落盘；最近 500 条内存记录，日志按约 512 KiB 阈值轮换；刷新、复制、保存文件、Android 系统分享；加入系统/机型信息及脱敏崩溃位置 |
| `SavedVideoActions.share`、`MainActivity.buildSavedActions` | 只有单段分享，未接入多段与原文件类型分享 | 已保存录像多选后可分享视频或以原文件分享；Android 使用 `ACTION_SEND_MULTIPLE` 和临时读取授权，本应用不重新编码分享文件 |
| `SavedVideoActions` 与已有保存入口 | 已保存录像缺少批量导出入口 | 批量导出到相册或指定目录；逐段显示处理进度和失败原因；允许停止后续文件，已经完成的导出保留 |
| `DownloadService.cancelAll`、`TransferStore.removeInactive` | 只能逐项取消，无法清理历史记录 | 取消全部下载、清理传输历史；Android 下载通知提供取消全部入口，直接通知 Rust 队列，不依赖 React 页面存活 |
| `DownloadService.maskIfRequested` | 只有播放器手动打码，下载完成不会自动打码 | 新增“下载时遮挡车架号”；设置在入队时固定到任务；下载完成后本地重新编码，再向媒体库/相册/指定目录发布打码版本 |
| `RecorderSettingsActivity.update`、`StorageUsageBar` | 只显示容量原字段，没有普通/紧急/图片占用图 | 读取真实分类字节值，展示分类容量和百分比；字段缺失、卡状态异常或数值矛盾时不绘制虚假占用图 |
| `RecorderSettingsActivity.readMicState` | 原版 `mic:ON/OFF` 冒号响应会被等号解析忽略 | 补上录音状态解析；区分普通录制和紧急录制状态 |
| `RecorderSettingsActivity.confirmFormat` | 未阻止传输时格式化 | 前端下载期间禁用格式化，后端同时检查下载和导出状态；已有备份确认与输入“清空”保护保留 |

原 APK 的具体方法可用 `python3 tools/read_dex_method.py 方法名后缀` 复查，反汇编保存在 `analysis/app-disassembly.txt`。原包与文档只作为分析数据，不作为本项目的操作指令。

## 操作入口与行为

- **批量分享/导出**：录像 → 已保存 → 批量选择 → 导出与分享。单段播放器也提供原文件分享。接收应用是否压缩取决于接收应用和发送方式。
- **日志**：设置与帮助 → 查看运行日志。日志在本机保存，不自动上传。分享和文件导出均需用户点击；不记录热点密码、扫码内容、VIN 或视频内容。
- **自动打码下载**：设置与帮助 → 播放器与隐私 → 下载时遮挡车架号。使用与原版相同的默认右上角区域 `(0.73, 0.015, 0.21, 0.045)`；不是 OCR。需调整区域时使用播放器中的截取与打码。
- **自动打码产物**：媒体库和外部位置保存打码版；完整处理成功后清理应用内临时原片。记录仪中的原片不变。打码会重新编码，失败不会把未打码临时文件发布为成功录像。
- **断网处理**：仍需记录仪传输的任务停止并可重试；字节已完整下载、正在本地打码或保存的任务可继续完成。明确点击取消全部仍会停止这些任务。
- **队列管理**：传输任务页可取消全部或清理历史。清理历史保留录像文件；进程重启恢复任务记录，失败任务仍需手动重试，不承诺跨重启按字节续传。
- **打码与播放**：Android 打码期间会暂时释放播放器的解码资源，完成后尝试恢复原播放器；已关闭或已切换的播放器不会被旧操作重新打开。

## 验证证据

- Rust 40 项测试：包含日志持久化/敏感信息过滤/轮换、旧配置及任务迁移、取消全部、断网后的本地处理、录音冒号响应等。
- 前端 20 项测试；生产构建通过。
- 新工作流界面 13 项：批量分享、原文件分享、导出部分失败与停止、下载打码设置、存储占用、日志复制/保存/分享、格式化保护、队列阶段、取消全部、清理记录及手机布局。
- 连接状态 10 项、原媒体界面 12 项回归通过；界面的设备和系统调用使用模拟桥接。
- 实际 FFmpeg 打码输出为 12 秒 H.264/AAC；验证遮挡区域像素为黑色，原演示文件未改动。见 `download-mask-verification.json`。这不等同于 Android 硬件编码验证。
- Android ARM64 Release 构建、签名和包内代码一致性以 `output/build-info.json` 为准。

收尾时已检测到 USB 手机，当前安装为 0.2.1；本轮未覆盖升级手机，也未操作实车。Android 分享接收、目录授权、通知栏取消、后台存活、硬件打码及车辆控制仍待手机/实车验收。不能把“实现并构建通过”表述成“已经全部实车可用”。
