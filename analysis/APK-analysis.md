# 银河记录仪 0.8.6：安装包分析与复刻方案

分析日期：2026-10-27。首个目标车型：2026 款星越 L，之后扩展其他车型。

## 结论

这款应用主要通过局域网访问原车行车记录仪，提供录像浏览、原画质下载、实时画面、片段截取与设备设置。复刻具有可行性；首要工作是验证 2026 款星越 L 的连接与协议，再实现新的界面。

安装包自带的 `assets/vehicle_names.json` 明确把“26星越L”归入 `A7` 配置。这里的 A7 是原应用使用的适配方案名，不表示把星越 L 识别成银河 A7。此配置证明原应用有对应的适配意图，不能代替实车可用性验证。

当前工作目录原本为空，没有可以直接改造的应用源码。后续需求已经确定为 React + Tauri，同时提供电脑版和手机版。本次工作包含静态分析、可追溯的反汇编证据及跨端项目初版；具体编译结果与尚未接入的功能以项目 README 为准。

## 分析范围与可靠性

- 读取 APK 压缩结构、Android Manifest、车型配置、DEX 字符串、441 个应用自身的类。
- 使用本机 Android SDK 的 `aapt2` 和 `dexdump` 核对声明、指令和调用关系，没有执行 APK 中的应用代码。
- 没有连接车辆、运行原应用、抓取车机通信，也没有请求安装包内的更新或统计服务器。
- 功能存在：由页面、调用和实现模块交叉确认。兼容程度：必须实车验证。
- 原界面问题依据 `MainActivity.onCreate` 的布局构建与文案分析，未取得原应用实际运行截图，不能据此判断其所有视觉细节。

## 2026 款星越 L：优先适配路径

原应用自带车型配置的关键内容：

```json
{
  "revision": "5",
  "models": {
    "A7": "银河A7/星耀7/M7/TT/26星舰7/26星瑞/26博越/26星越L/星愿",
    "E5": "银河E5/星耀8/25星舰7/25星瑞",
    "GENERIC1": "通用模式一",
    "GENERIC2": "通用模式二",
    "L6": "银河L6/L7/23 24领克07/08"
  }
}
```

配置中的车型名称可以由服务器更新；它们不构成已经测试通过的车型清单。代码另有第三种通用方案，映射到 L6；通用一映射 E5，通用二映射 A7。

2026 星越 L 的初始流程应为：开启车机热点 → 手机连接热点（手动/扫码）→ 必要时在车机打开一次原厂记录仪应用 → 寻找记录仪 → 读取列表 → 播放或保存。

这里“手机连上热点”和“已经找到记录仪”必须是两个不同状态。原应用的 `Discovery` 结合 HTTP 识别和 UDP 监听探测设备，文案中有 IPv4 网段扫描、450ms HTTP 超时、最长 35 秒等实现信息；这些是原实现参数，不是首版必须照搬的体验指标。首先尝试记住的地址，再尝试当前网络的候选设备，最后才进行有界扫描。

### 已找到的协议线索

1. HTTP 设备接口族：`/cgi-bin/Config.cgi?action=...&property=...`。
2. 录像目录接口模板：`/cgi-bin/Config.cgi?action=dir&property={category}&format=all&count={count}&from={offset}`。2026-10-27 逐方法核实：A7 分类属性为普通 `DCIM`、紧急 `EVENT`；`MOVIE / SOS` 属于 usesMstar 分支，不能用于当前星越 L 适配。实际列表响应仍需实车确认。
3. 实现中存在 `DVR`、`Camera.Menu.*`、`Camera.Menu.FWversion`、`Camera.Menu.HeartBeat`、`Camera.Menu.CardInfo.*` 等查询。不同方案及固件的属性集合有差异，不能保证所有字段都适用于星越 L。
4. 实时预览包含 RTSP 协商及 `/liveRTSP/v1`、`/liveRTSP/av0`、`/liveRTSP/av1`、`/liveRTSP/av2`、`/liveRTSP/av4` 等候选路径，应协商并记住成功结果。
5. A7 列表模块有分页参数回退、重复条目去重、短页和不完整响应处理。复刻时应保留这些兼容思想。
6. HTTP 字节范围读取用于在线播放、片段提取和下载校验，需要核对服务端的 Range 与文件长度行为。

以上是从应用中提取的接口族与候选流程，不是经 2026 星越 L 验证的完整接口文档。设备 IP、HTTP/RTSP 端口、分类目录、响应 XML/文本格式及指令语义仍待实测，不能把某个固定 IP 写死。

### 第二阶段的其他车型

- E5 方案：原应用偏向直接搜索并连接记录仪 Wi-Fi；存在原厂名称匹配规则，与 A7 的车机热点路径不同。
- L6 方案：另有 Vyou HTTP JSON 接口（`/vcam/cmd.cgi?cmd=...`）、设备会话、UDP 发现与 TCP 私有视频帧通道，不能只替换车型名称。
- 型号、年款和记录仪固件应共同决定能力。新增车型应增加适配器与能力表，避免把所有差异放进页面判断。

## 界面优化提案

原首页的布局构建同时包含车型选择、连接入口、无线网络、实时画面、设备设置、说明、手动地址、普通/紧急/已保存分类、日期筛选、多选、打码和保存。我的判断是：主要问题在于任务层级混杂，单纯更换配色无法解决。

建议使用四个稳定入口：

- **设备**：2026 星越 L、热点/设备连接状态、连接入口、实时画面。故障时直接给下一步。
- **录像**：普通/紧急分类，按日期分组，缩略图、时长、保存状态。选择录像后才出现批量操作。
- **传输**：当前任务、等待任务、进度、取消及失败重试；只有经过实际测量才显示速度和预计时间。
- **设置**：录音、存储卡、固件、车型、帮助及诊断。手动地址放在连接的高级选项中。

播放器单独承载截取、打码、保存与分享；格式化放在存储管理的次级入口并保留明确确认。普通录像和紧急录像使用文字标记及少量颜色辅助识别。帮助、作者信息、公告不占据录像浏览的主要区域。

当前 React 初版已实现桌面侧栏、手机底部导航及自适应录像布局；最新设计以手机版为优先，采用瓷白、银灰与冰蓝的浅色科技风，不提供深色切换。演示模式使用示例数据，真实模式通过 Tauri 调用 Rust 设备层；具体完成情况见 README。实车兼容性尚未验证。

## 实现建议

技术栈已经按用户要求确定为 **React + TypeScript + Tauri 2**。React 共享页面与业务状态，桌面使用侧栏与网格布局，手机使用底部导航与自适应布局；Rust 层承担设备 HTTP、协议解析、发现与文件传输。Android 的网络选择、扫码、后台服务、相册导出和实时视频分别通过原生插件扩展。手机端首先面向 Android，iOS 的构建需要 macOS/Xcode 环境。依据：[Tauri 前置条件](https://v2.tauri.app/start/prerequisites/)、[Tauri 移动插件开发](https://v2.tauri.app/develop/plugins/develop-mobile/)。

建议的职责划分：

```text
React 页面：设备 / 录像 / 播放器 / 传输 / 设置
  ↓
连接状态管理、录像索引、传输队列、导出管理
  ↓
RecorderAdapter 接口与能力表
  ├─ A7Adapter（首个目标：2026 星越 L）
  ├─ E5Adapter（后续）
  └─ L6Adapter（后续）
  ↓
Tauri Rust 设备层 + Android 原生网络/视频/存储插件
```

记录仪流量应明确使用选中的 Wi-Fi 网络；Android 的 `Network.openConnection` 与 socket API 支持将连接定向到指定网络，可用于处理“热点无互联网、手机仍有蜂窝网络”的情况。依据：[Android Network 文档](https://developer.android.com/reference/android/net/Network)。

Tauri WebView 中的本地视频播放取决于平台解码支持；RTSP 实时画面不能仅把地址交给 HTML video 就视为已接入。Android 原生视频插件可以评估 AndroidX Media3；片段编辑、覆盖处理可评估 Transformer，最终仍需用真实片源检查兼容与耗时。依据：[Media3 Transformer 文档](https://developer.android.com/media/media3/transformer)。

安装包的 `VinMaskRegion` 使用固定比例区域（左 0.73、右 0.94、上 0.015、下 0.06）。这是固定位置遮挡，未见该模块进行 OCR 自动识别。新版应允许预览与调整遮挡区域，防止不同分辨率、画面旋转或水印位置导致漏遮。打码涉及重新编码，应如实显示画质和耗时影响。

原应用还有独立服务器通信，包含更新、公告、车型配置和使用统计；统计载荷包含设备标识、机型、系统和应用版本、网络类型等字段。这些不是记录仪本地传输的必要条件，复刻版应自主设计，并让诊断上传由用户主动触发。本文未访问这些服务。

## 首版实施与验收顺序

1. **连接闭环**：在 2026 星越 L 上完成热点连接、设备发现、网络断开与重新连接；先只读获取状态和列表。
2. **录像闭环**：普通/紧急列表、分页、日期筛选、缩略图；读取不完整时保留已读数据并提示。
3. **保存闭环**：播放一段录像、下载到相册、核对文件完整性、分享；覆盖 Wi-Fi 无互联网且手机开着移动数据的场景。
4. **传输体验**：队列、取消、任务失败重试、后台通知、空间不足与中断处理。是否实现跨重启续传需单独定义。
5. **增强功能**：实时画面、截取、打码。录音和录制控制逐项核实设备支持情况；格式化最后验证。
6. **扩展车型**：先扩展相同协议族且响应兼容的车型，再增加 E5、L6 的独立协议适配。

实车联调最少需要：手机系统版本、车机/记录仪固件版本、连接结果，以及经过脱敏的状态/列表响应或诊断日志。无需提供 Wi-Fi 密码、VIN 或私人录像。界面开发可使用模拟数据提前进行，真车功能验收必须在可达记录仪的环境完成。
